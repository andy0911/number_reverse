# 合議（トオカエシ）

プロダクトに関わる意思決定は、単独で決めず、この手順で行う。

## 参加者（それぞれ独立したサブエージェントで起動する）
| 役割 | 定義ファイル |
|---|---|
| マーケティング専任者 | `.claude/agents/marketing-specialist.md` |
| プロダクトマネージャー | `.claude/agents/product-manager.md` |
| プロダクトデザイン責任者 | `.claude/agents/product-design-lead.md` |
| スクラムマスター（意見を出さない進行役） | `.claude/agents/scrum-master.md` |

サブエージェントとして登録されていない環境では、general-purpose のサブエージェントに「該当の定義ファイルを最初に読み、その役割として振る舞う」と指示して起動する。

## 手順
1. **論点の定義**: 決めること、判断期限、関係するインセプションデッキ項目（`docs/inception-deck.md`）、使う材料（実測値・出典）を書く。実測値が古い場合は先に最新化する
2. **第 1 ラウンド（独立）**: 3 専門家に、役割定義・論点・共通の事実データ（`docs/facts.md`、デッキ）だけを渡し、並列で意見を求める。呼び出し元の会話の経緯・互いの意見は渡さない
3. **整理**: スクラムマスターが意見を要約し、一致点・対立点・前提の違いを表にする
4. **第 2 ラウンド（対立点のみ）**: スクラムマスターが対立点を、誰の意見かを伏せた中立な論点に書き直し、3 専門家に問い直す。他者の意見はそのまま渡さない。必要なときだけ行う（最大 2 ラウンドまで）
5. **決定案**: スクラムマスターが合意案、または選択肢を支持役割と根拠付きでまとめる。多数決にしない
6. **報告**: あんでぃさんに、各役割の意見・対立点・決定・根拠を残して報告する
7. **承認**: お金がかかる操作、広告の変更、審査提出、App Store メタデータの反映は、あんでぃさんの明示の承認があるまで実行しない

## コンテキスト共有の禁止（あんでぃさんの指示。専門性を保つため）
- 専門家が受け取るのは、自分の役割定義、議題、共通の事実データ（`docs/facts.md` とデッキ）だけ。呼び出し元の会話の経緯も他の専門家の意見も渡さない。
- 突き合わせはスクラムマスターだけが行う。専門家には `docs/consensus/` を読ませない。
- デッキ自体には役割別の意見を書かない（役割別の意見は決定記録にだけ残す）。

## 規律
- 決定はデッキと矛盾させない。矛盾する場合はデッキの更新も合議で決める
- 数値は「実測（出典付き）」と「推測」を分けて渡す
- スクラムマスターは意見を出さない。評価語・推奨を書かせない
- 緊急の事故対応（本番障害の復旧など）を除き、この手順を省略しない
