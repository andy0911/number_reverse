# 難易度の校正（人間代理プレイヤーとの対戦シミュレーション）

最終更新: 2026-10-13（build 38 の「つよい」を測定）

## 結論

- build 38 の「つよい」（6手読み・終盤11マス全読み・ゆらぎなし）に対する人間代理の勝率は **8.5%（200局中17勝、95%信頼区間 5.4–13.2%）**。
- 同じ代理・同じ seed 0–199 で測った 1 つ前の「つよい」（v1.1.5）は 18.5%（200局中37勝）。勝率はおよそ半分になり、目標の 10% 以下を点推定では満たす。区間の上端は 13% なので「10%以下」と断言できるほどの試行数ではない。
- 強めの人間代理（温度0.3・位置評価あり）相手でも 9.0%（100局中9勝、4.8–16.2%）。v1.1.5 の「つよい」はこの代理に 23.0%（200局）負けていた。
- 代わりに 1 手の思考時間が長い。Linux コンテナ（x86_64 の 1 コア）で平均 約2.8秒、最長 25.6秒。端末では速さが違うので実機での確認が要る。

## 方法

### 人間代理プレイヤー

人間の代わりに、次の設定の `ReadingAI` を使う（`Core/Sources/Calibrate/main.swift` の `humanProxy`）。

| 項目 | 値 |
|---|---|
| 読みの深さ | 2手 |
| ゆらぎ（softmax 温度） | 0.1 |
| 位置評価 | なし |
| 爆弾の方向を誤る確率 | 0.1 |
| 手駒の記憶誤り・相手モデル | なし（既定値） |
| 終盤全読み | なし |
| ルート/各局面の幅・ノード上限 | 既定値（12 / 6 / 200,000） |

v1.1.5 の校正（コミット 7f6f33b）で使った代理の正確な設定はリポジトリに残っていない。「2手読み・低ゆらぎ」という記述から候補を作り、v1.1.5 のプリセットに対する勝率が当時の値（74% / 47% / 15%）に近いものを選んだ。

| 代理の設定 | かんたん | ふつう | つよい(v1.1.5) | 局数 |
|---|---|---|---|---|
| 温度0.3・位置評価なし | 61.5% | 43.5% | 10.8% | 各400 |
| **温度0.1・位置評価なし（採用）** | **75.5%** | **56.3%** | **17.0%** | 各400 |
| 温度0.3・位置評価あり | 73.0% | 59.0% | 23.0% | 各200 |
| 温度0.1・位置評価あり | 84.0% | 71.0% | 35.5% | 各200 |

採用した設定は、かんたんとつよいは当時の値とほぼ一致し、ふつうは 9 ポイント高い（56% と 47%）。当時の代理とは完全には同じでないので、絶対値よりも同じ代理で測った前後比較のほうが信頼できる。

### 対局の進め方

- `GameState()` の初期状態から、初期配置を含めて終局まで打つ。爆弾の方向は、裏返された爆弾の持ち主の AI が選ぶ。
- seed が偶数なら代理が先行、奇数なら後攻。乱数は SplitMix64（`AITests` と同じ）で、seed から再現できる。
- 駒数が多い方の勝ち。同数は引き分けで、人間側の勝ちには数えない。
- 4 プロセスに seed を分けて並列に回した。

### 実行方法

```bash
cd Core
swift build -c release
.build/release/calibrate hard 200 0      # 難易度 / 局数 / 開始 seed
```

1 局 1 行の TSV（seed、代理の手番、代理の駒数、CPU の駒数、結果）と、最後に `#` で始まる集計行（勝敗と CPU の 1 手あたり思考時間）を出す。

- 代理の設定は環境変数 `PROXY_TEMP`（温度）と `PROXY_POS`（位置評価の重み）で変えられる。
- `custom` を指定すると「つよい」（`C_BASE=hardPrevious` なら 1 つ前のつよい）を基に `C_DEPTH`・`C_END`・`C_ENDBUDGET`・`C_NODES`・`C_ROOT`・`C_BREADTH`・`C_TEMP`・`C_POS`・`C_BOMBERR` で上書きした設定を測れる。

## 結果

### build 38 の「つよい」

| 相手 | 人間代理の勝率 | 内訳（勝/負/分） | 先行時 | 後攻時 | 局数 |
|---|---|---|---|---|---|
| 採用した代理 | **8.5%**（5.4–13.2%） | 17 / 182 / 1 | 6/100 | 11/100 | 200 |
| 強めの代理（温度0.3・位置評価あり） | 9.0%（4.8–16.2%） | 9 / 90 / 1 | 4/50 | 5/50 | 100 |

- 全局の平均駒数差（CPU − 代理、seed 0–199）: build 38 は 27.8 枚、v1.1.5 は 16.0 枚。
- CPU の 1 手の思考時間（コンテナ上、300 局分）: 平均 2.6–3.1 秒、最長 25.6 秒。

### v1.1.5 のプリセット（再測定）

| 難易度 | 人間代理の勝率（95%信頼区間） | 局数 | 当時の値 |
|---|---|---|---|
| かんたん | 75.5%（71.1–79.5%） | 400 | 約74% |
| ふつう | 56.3%（51.4–61.0%） | 400 | 約47% |
| つよい | 17.0%（13.6–21.0%） | 400 | 約15% |

### 参考: 「つよい」の読みの深さだけ変えた試行

v1.1.5 の「つよい」（`hardPrevious`）を基に、`custom` で深さを変えて 100 局ずつ測った（ノード上限 200,000、終盤 7 マス）。再現するには `C_BASE=hardPrevious C_DEPTH=6`。この試行だけは先後の割り当てが古い版（seed の偶奇でなく各プロセス内の順番）で、先行 52 局・後攻 48 局になっている。

| 深さ | 人間代理の勝率 | 100局の所要時間（4並列） |
|---|---|---|
| 4 | 15.0% | 56 秒 |
| 6 | 11.0% | 259 秒 |

深さを 6 にしても 15–17% から 11% 程度までしか下がらず、build 38 の 8.5% との差は主にノード上限の引き上げ（1,500,000）と終盤全読みの拡大（11 マス）による、と推測する（未検証）。

## 限界

- 代理は AI で、人間の癖（序盤の定石、読み抜けの偏り）は再現していない。実際の人間の勝率とは違い得る。
- 200 局では ±4 ポイント程度の幅がある。10% を境に判断するなら 1,000 局ほど欲しいが、build 38 の「つよい」は 1 局約 75 秒（1 コア）かかるため今回は 200 局にとどめた。
- 思考時間はコンテナでの値で、iPhone での値ではない。1 手の思考時間は手の選択だけで、爆弾の方向選びは含まない。
- 「温度0.3・位置評価あり」の行、深さ 4 の試行、思考時間はコンソールの集計行から転記した（対局ごとの TSV は残していない）。今後は集計行に代理と CPU の設定も出る。
