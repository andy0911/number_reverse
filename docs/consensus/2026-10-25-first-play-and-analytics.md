## 初回導線（起動〜最初の1局の初手）の棚卸しと改善案 2026-10-25

方法: App/ と Core/ のコード読み（実機・シミュレータは未使用）。秒数は推測。改善案の優先度は、専門家3体（マーケ・PM・デザイン）の独立意見をスクラムマスターが整理した合議の結果。実装は未着手（承認待ち）。

## 1. 現状の経路と摩擦（実測＝コード読み）
最短経路（CPUと対戦・先行・おすすめ難易度）:
起動 →（初回のみ ATT の許可ダイアログ +1）→ 「CPUと対戦」1 → 難易度1 → 初期配置の人間の3手×2タップ=6 → 本戦の最初の1手 2 
- 初期配置が終わるまで 8タップ、本戦の最初の1手を打ち終えるまで 10タップ（ATT除く）。
- 秒数（推測）: 初期配置終了まで約10〜20秒、ATT初回は +3〜5秒。要・実機計測。

摩擦:
1. 初期配置6手（原案のルール）は盤面が変わらず、画面は「初期配置 2-1：先行が赤マスの自陣側に数字駒を置く」と、手順番号・赤マス・自陣側を説明なしで使う。
2. 駒を選ぶまで置けるマスが出ない。選ばずに盤を触ると赤字「先に下から駒を選んでください」。
3. 初期配置から本戦に入っても切り替えの案内がない。「合計で挟んで返す」の説明はゲーム画面内になく、遊び方に集約されている。
4. 遊び方は12レッスン。裏返りの実演は3番目で、先頭から進むと約15タップ、メニューから選ぶと3タップ。初回の誘導も、ゲーム中から開く入口もない。初回判別の仕組みもない。
5. 起動直後に ATT（日本では UMP のフォームなし）。タイトルは広告削除・購入復元・プライバシー設定が並ぶ。
6. CPU の手番は固定 600ms 待つ（影響は小さい見込み）。

## 2. 合議の結果
3者一致（決定案）:
- (a) 初期配置の画面文言を、spec 用語と整合する平易な言葉に直す（「10で返す」と読める文は不可）。
- (b) 初期配置→本戦の切り替えに1行の案内を出す（spec §5.1「自軍の合計＞相手軍の合計」と照合）。
- (c) 触らない: 広告枠・頻度・契機・位置、ATT/UMP、ルールと初期配置6手の順序、「原案: @bdgame_」、「もう1局」。
- (d) 完了判定は計測SDKなしの観察（初見の人・説明なし・実機・件数）。
- (e) 秒数の絶対値目標は、改善前の基準値を取ってから置く。

意見が分かれた点（あんでぃさんの判断待ち）:
| 論点 | 選択肢（支持した役割） |

## 3. 完了基準の案（計測SDKなし）
- 対象: 初見の人 3〜5人（説明なし・実機・画面収録）。改善前に同手順でベースラインを取り、改善後に再観察。統計的な有意性は主張せず、件数で判断。
- 記録: 起動→初期配置完了と初手までのタップ数・秒数／赤字エラーの回数／3秒以上止まった画面と疑問／遊び方を押したか・核まで何タップか／最初に「挟んで返す」に至った手数／終了後に「赤マス」「自陣側」「手駒」の意味と「ルールを一言で」を聞く。
- 合格線の案: タップ数は現状の10を増やさない／全員が助けなしで初期配置を置き終える／赤字エラーが改善前より減る／止まった箇所が再現しない／5人中3人以上が「合計が大きいほうが挟んで返せる」趣旨を自分の言葉で言える（「10で返す」は誤読として記録）／秒数は基準値から短縮か同水準。
- 1回で満たさなければ1回だけ手直し再観察。それでも未達なら「できる範囲まで」と記録して打ち切る。
- 10秒・20秒・人数・4/5・3/5はいずれも推測の仮置き。

## 計測SDK導入の合議結果 2026-10-25（第1ラウンドのみ）

きっかけ: あんでぃさん「計測SDKを入れても良い」（検討の許可。実装・審査提出・申告反映の承認ではない）。デッキ第6項【決定】（新規の外部分析SDKは入れない／端末内カウンタは1ヶ月目に入れない）の見直しにあたる。SDKの料金・規約・収集範囲・申告上の扱いは3者とも未確認（要確認）。

## 3者が一致した点（決定案）
1. 1ヶ月目前半は導入しない。
2. 先にASC App Analyticsで見える範囲を確認する（あんでぃさんの画面確認が要る）。人手の観察も続ける（SDKは「どこで止まるか」、観察は「なぜ」）。
3. 申告・PrivacyInfo・同梱マニフェストの不一致（現状は全件Not linked）を、新しい送信より先に直す（提出なし）。
4. 1ヶ月目末のゲートで再判定する。入れるなら無料・サーバー運用不要・個人非特定・IDFA不使用の方向（TelemetryDeck型が候補）。Firebaseと自前送信は第一候補にしない。
5. 分析はIDFAを使わず、ATTの許可に依存しない。広告用IDと混ぜない。起動時に新しい許可ダイアログを足さない。
6. イベントは固定の列挙のみ。盤面・手・座標・スコア・端末固有ID・位置・自由文字列は送らない。広告の枠・頻度・体験は変えない。
7. 共通で取るイベント: 最初の1局の初手・完走、2局目の開始、遊び方を開いた回数。
